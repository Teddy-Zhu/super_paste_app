## 启动黑屏与托盘

本机原 dev 二进制在第一次 `desktop_bootstrap` 请求时发生 SIGSEGV。GDB 定位到 `commands::dispatch` 函数入口的栈探测指令；调试构建的分发函数单层栈帧约 618 KiB，多层异步 IPC 包装累积超出 Tokio 默认线程栈。

分发函数现返回堆上的 `BoxFuture`，避免将大状态机继续嵌入每层生成的 IPC 包装。保留启动完成和 bootstrap 完成的日志，便于区分 Rust 初始化与前端配置加载。没有通过增大所有线程栈或屏蔽信号绕过问题。

`libayatana-appindicator is deprecated` 是现用 Linux 托盘后端的上游弃用警告，与上述栈溢出的定位证据不同。新 `libayatana-appindicator-glib` 使用不同的菜单接口，不能仅替换动态库名称。Linux 托盘点击事件受 Tauri 后端限制，业务操作通过托盘菜单提供；本机已取得完整 DBus 菜单，设置与退出动作均已触发。[Tauri 托盘文档](https://v2.tauri.app/learn/system-tray/)、[Ayatana 新接口](https://github.com/AyatanaIndicators/libayatana-appindicator-glib/)。

## Rust 实现调整

- 对 IPC 大 Future 使用堆分配，限定异步包装层的栈占用。
- OCR 同图任务在写回边界原子关闭接收，取消仅作用于实际关联且已无剩余记录的任务；MCP 即时请求独立处理。
- 本地 OCR 线程区分队列空闲与通道关闭；退出始终回收线程，避免空闲后识别不可用及清理漏报。选中模型重下载保留队列，等待在途任务完成，并在成功或失败后恢复调度。
- 历史清理使用集合 SQL 和实际删除结果；复制分类正则只编译一次；退出先停止监听并等待已接收的采集完成，避免后台仍在写入时提前刷新数据库。
- 图片在识别和网络请求路径中转移所有权，减少大缓冲区克隆；避免同一记录重复入队先读取整图。
- 同步关闭与配置串行协调，等待网络任务前释放配置锁；MCP 推送受限并发，Portal 操作可取消并限时关闭。

## 保留的产品边界

独立数据和一次性迁移、新应用身份、新 WebDAV 格式、凭据仅保存在本机、新 MCP 端口/密钥及诊断导出，均按已确定方案执行。远程 OCR 地址和自由额外参数作为本机配置，不随 WebDAV 同步。未增加旧数据运行时兼容层。

本机运行环境是 Linux KDE X11。Windows、macOS、KDE Wayland、实际 OCR 模型/第三方 AI 与 WebDAV 服务、安装包和真实数据迁移仍需对应环境验收；不能用本机编译结果代替这些运行结果。UI 由用户验收。
