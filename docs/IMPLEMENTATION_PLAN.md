# Super Paste 实施方案

本文件定义迁移范围、行为契约和完成标准，不作为当前完成进度。原 `super_paste_rs/` 已提升为仓库根项目，旧 Vue/Tauri 实现已移除；下文旧源码路径只指 Git 历史中的复刻基准。运行说明及当前状态见 [README](../README.md)，旧实施记录见 [历史归档](README-history-2026-11-19.md)。

### 已确定的实现边界

- 历史卡片以清晰展示剪贴板内容、便于辨认和浏览为目标，可按 GPUI 现有能力自行布局；尺寸、字号、间距、换行、截断与装饰不要求逐项复刻原版，不为卡片的这些视觉细节继续扩展底层文字引擎，也不以重新设计卡片为前置工作。内容、加载/失败反馈、选择、菜单、快捷键与还原语义保留；优先完成业务闭环与资源回收。
- 除历史卡片和详情阅读窗口外，其他界面以功能、交互语义、布局尺寸和动画参数一致为标准，允许 GPUI 与 WebView 的字体栅格化、抗锯齿细微差异；不以此放宽明显的尺寸、换行或命中偏差。
- 应用内容坚持 GPUI 原生绘制。Kit 存在能力缺口时允许维护限定范围的源码补丁，不嵌入 WebView，也不静默降级现有功能。
- 历史详情使用独立的原生居中阅读窗口，尺寸按内容类型、长度、图片比例及所在屏幕工作区确定，支持调整尺寸、最大化、选择复制及原文切换。打开时保持面板可见并保留查询与浏览状态，焦点在面板与详情间切换不关闭面板，关闭详情的焦点回交期间也不触发面板隐藏；关闭详情返回面板，Esc/Ctrl/Cmd+W 只关闭详情，全局面板快捷键关闭整个查看会话。详情拥有所在窗口的图片绘制资源，继续共享后台原图、解码及文档服务；记录删除、失效和宿主退出均回收详情。
- 其余应用内弹窗，包括原系统确认、成功和错误消息，统一使用 GPUI Kit Dialog。弹窗壳的外观、焦点、模态、进入退出和关闭行为采用所选版本默认值，不复刻旧弹窗壳；业务内容、操作条件和结果含义保留。
- 文件选择器与托盘菜单仍可使用系统能力。页面内的状态、字段错误与进度继续在原位置展示，不因统一弹窗而全部改为消息框。
- 完整交付目标是 Windows、macOS、Linux X11 和 KDE Plasma 6 Wayland。其他 Wayland 环境只列明实际支持的能力，本轮不扩展为同等功能支持。
- 本轮不实现旧数据导入。首次启动初始化独立数据和凭据空间；初始化后的历史、标签和统计为空，配置使用迁入的默认值。
- 复刻约束面向用户可见行为和业务语义，不要求沿用旧数据库物理格式、IPC DTO、缓存层次或优化参数。内部实现按 Rust + GPUI 的单进程模型重新设计，优先减少重复存储、编解码、复制和无效刷新。

## 一、独立项目边界

- 所有代码、资源、配置、脚本、依赖锁文件和平台补丁均归属当前仓库；构建产物放入被忽略的 `target/`、`dist/` 和 `release-assets/`。
- 根目录使用独立 Rust workspace，不保留旧 Vue/Tauri 宿主、pnpm 构建或旧数据迁移器；开发与发布只接入本项目的 Rust 和 Node 脚本。
- 父项目只作为迁移时的行为和源码参考。需要复用的代码、图标、模型清单和 vendor 补丁，复制到本项目后独立维护，保留来源、许可证和必要说明。
- 禁止通过父目录 `path` 依赖、`include!`、资源相对路径、符号链接、构建脚本读取父目录等方式形成隐式依赖。
- 本目录应能够单独复制或检出到其他位置，通过自身声明的依赖和资源完成构建。
- 本项目保留自己的 `Cargo.toml`、`Cargo.lock`、版本、开发命令和打包配置。产品版本以本项目根 `Cargo.toml` 的 workspace package version 为唯一人工维护来源。
- 新项目根 `Cargo.toml` 显式声明独立 `[workspace]`，避免 Cargo 将它误判为父 workspace 成员；构建与格式化从本目录执行。
- 代码独立不要求另建或嵌套 `.git`；本轮不初始化仓库、不提交、不推送。

运行隔离采用独立应用标识，建议为 `com.v2dawn.superpaste.rs`，并使用独立数据目录、凭据命名空间和单实例标识，具体平台标识在宿主实现时统一确定。不得读写旧应用的活动数据库、自动接管旧凭据或扫描导入旧数据。本轮不创建导入入口或迁移器；后续若需要导入，作为独立需求定义。

新项目创建自己的 `.gitignore`，覆盖本项目 `target/`、下载的运行库、缓存和打包产物。父项目根的 `/target/` 规则不覆盖本目录下的 `target/`，不能依赖父项目忽略规则完成隔离。

全局快捷键、MCP 端口等系统资源不能因应用标识独立而自动隔离。注册或监听冲突应返回明确错误，不静默抢占旧应用资源。

| 能力 | 选型 | 实现要求 |
| --- | --- | --- |

| 标准控件 | Kit 的 `gpui-component` 层 | 统一包装和主题定制 |
| 自定义交互基础 | Kit 的 `gpui-base` 层 | 复用输入、焦点、菜单、弹层和选择行为 |

| 虚拟列表 | Kit 横向、纵向 VirtualList | 负责可见范围渲染与滚动控制 |
| 富文本 | Base TextView | 复用常见 HTML 排版、选择和复制，补齐格式缺口 |
| 统计图表 | Kit Chart，必要时局部 GPUI 绘制 | 保持现有刻度、标注和外观 |
| 图标 | 从旧项目迁入实际使用的 MDI SVG | 通过 `AppIcon` 集中映射，不整体替换为 Kit 默认图标 |
| 文件对话框 | 优先 GPUI 平台接口，缺口评估 `rfd` | 统一父窗口、异步完成、取消和失败处理 |
| 托盘 | Windows/macOS `tray-icon` 0.26.0，Linux `ksni` 0.3.6 + GTK 3 `gtk` 0.18.2 XEmbed 后端 | 平台实现统一到托盘服务接口 |
| RTF | 优先评估结构化解析器，如 `rtf-parser`；`rtf-to-html` 仅作有明确理由的适配候选 | 按 4.7.3 节统一文档结构，不假定基础转换器覆盖原有全部格式 |
| 图片色彩与 PQ／HLG 显示 | MoxCMS 0.8.1 + Gainforge 0.4.1 | 共用原生解码和有界行缓冲，保留高位深至显示映射结束；原始像素不做显示变换 |
| 数据库、OCR、同步、凭据、二维码 | 复用业务规则和适用的 Rust 实现 | 存储布局、数据传递与缓存按新架构重设计；代码和资源全部归属新项目 |

依赖实施规则：

1. 选择具体 Kit 版本后，以对应版本源码为准核对 API，不能混用主分支文档和旧版本示例。
2. Kit、Base、Component 和 GPUI 必须使用同一套兼容版本，维护新项目自己的锁文件。
3. 默认使用 Kit 配套后端；不同时引入多个 GPUI 分支或其他完整 GUI 框架。
4. 第一版不引入独立动画库，Base Motion 已覆盖当前过渡、关键帧和进入退出需求。
5. 不启用 JavaScript 扩展运行时、WebView 或应用未使用的编辑器语法树等能力。
6. 当前代码预览没有语法高亮，复刻时保持等宽文本；不因生态支持而扩展产品行为。
7. 确需修补上游时，固定补丁来源和版本，集中记录变更，不让应用代码依赖不明来源的改造分支。

选定版本后记录工具链、系统开发依赖、渲染后端和功能开关，以及输入法、Dialog、VirtualList、TextView、透明窗口、帧提交和平台扩展的对应接口。区分文档宣称能力、所选版本源码能力与已验证能力；实际缺口必须有实现归属，不能以候选库名替代实现。

## 四、迁入并解耦 Rust 业务

### 4.1 核心服务

复用配置、剪贴板业务、OCR、同步、MCP 和凭据的适用实现，保留现有业务规则。存储与格式模块参考旧实现重新组织，不要求逐文件搬运或保持旧 schema。复制完成后，后续修改只落在新目录。

- 将原 `Runtime` 的 `AppHandle`、窗口管理和插件调用移到新宿主。
- 用显式持有的 Tokio Runtime/Handle 替代 `tauri::async_runtime`。
- 将数据路径、资源路径、ORT 路径、应用版本等通过启动上下文传入。
- 数据库访问、OCR、解码、下载和网络操作不在 GPUI render 或 UI 回调中阻塞执行。
- 配置服务继续持有权威配置；UI 显式提交，后台校验后返回结果。
- 保留设置窗口与浮层的操作范围约束，调用入口携带明确来源。
- MCP 请求与会话取消贯穿历史搜索、记录及 OCR 图片来源读取、图片处理和响应编码；SQLite 排队读取取消后不执行 SQL，运行中的查询复用作用域进度检查。设置剪贴板在平台交接前接受取消，已交接操作按真实写入结果结束，不将已完成写入改报为取消。
- 凭据只写系统凭据库；WebDAV 仅同步非敏感设置。
- 同步测试和手动同步拒绝已取消的调用；已接收任务在执行前先处理调用方取消，凭据读取开始前及返回后复核取消。正在执行的凭据读取正常收尾，已由配置服务接收的提交等待真实结果，前台等待和停服收尾均返回实际提交或回滚结果，不提前误报为取消。
- OCR 模型准备阶段协作取消，目录替换开始后等待安装或回滚收尾并返回真实结果；期限只把由本次超时触发的准备取消标记为超时，不覆盖已完成安装或实际文件操作失败，也不重新标记先前的调用方取消。
- 不引入历史数据库同步，也不把 Electron 兼容或一次性迁移器接入运行路径。

### 4.2 事件与 UI 状态

从首次接入开始使用类型化 `AppEvent` 和服务调用，覆盖历史、标签、OCR 任务、模型、配置提交、统计、MCP 和同步。旧 `EventSink` 仅作为事件覆盖范围的参考，不作为新宿主的中间桥接格式。

- Tokio 任务持有后台服务，GPUI 主线程持有窗口、Entity 和控件状态。
- 后台结果通过事件桥进入 GPUI，不跨线程直接修改 UI Entity。
- 任务持有窗口或视图的弱引用；视图销毁后丢弃结果并释放订阅。
- 历史与配置通知发生滞后或丢失时重新读取快照，避免永久停留在过期状态。
- 高频进度更新合并刷新；终态必须送达或可通过状态重读恢复。
- 用类型化 Rust 调用替换字符串 IPC，不复制 Vue/Pinia/Tauri IPC 桥。
- 内部事件携带 ID、修订、状态或共享快照引用，不为跨线程通信先序列化为 JSON 再还原。JSON 编解码限定在必要的持久化与外部协议适配层。

### 4.3 剪贴板读写与持久化契约

现有行为参考 `src-tauri/src/core/clipboard.rs`、`core/clipboard_content.rs`、`storage/clipboard.rs` 和 `storage/mod.rs`；这些路径是 Git 历史中的旧项目调查索引，运行时不得依赖它们。

| 操作或数据 | 必须保留的语义 |
| --- | --- |
| 普通还原 | 从完整记录构造快照，写回同时存在的 text、HTML、图片、RTF、files，不只写预览主类型 |
| 还原为纯文本 | 按迁入的 `plain_text` 规则依次使用非空白文本、HTML/RTF 提取、文件路径等；只写文本，不携带原有其他格式；不可提取时返回原有错误 |
| 还原 OCR | 只写对应记录的 OCR 文本；缺少 OCR 文本时失败 |
| 文件格式 | 保存和还原路径列表，不复制或打包文件实体，不承诺已删除源文件仍可访问 |
| 操作完成 | 仅写系统剪贴板并执行现有浮层收尾，不模拟 Ctrl/Cmd+V、不注入键盘事件 |
| 还原与二维码取消 | 交给系统前可取消来源读取和处理；排队取消跳过 SQL，运行中的只读取消作用域及事务先收尾，不影响下一条写入。已交给系统的写入按真实结果结束，不因调用方离开改报取消 |
| 多格式与预览 | 存储主类型、可用格式和 UI provider 优先级分别保持；不得以预览结果覆盖原始数据 |
| 去重 | 保留连续重复通知抑制、多格式内容等价及图片像素等价的业务语义；摘要表示和计算流水线可重设计，命中后保持原记录及现有使用时间、来源更新规则 |
| 自动保存 | 保留先记录有效复制统计、再判断是否保存历史的顺序；关闭自动保存不等于停止监听或停止统计 |
| 监听与清理 | 监听启停、历史数量和时间清理、标签关联及 OCR 任务取消继续走既有业务路径；采集入库、去重命中后的元数据更新与保留策略清理使用同一事务，提交后再发布历史事件和调度 OCR；未删除记录时不扫描孤立图片 |
| 数据库 | 使用本项目独立格式标识、schema 版本和初始化逻辑；不要求兼容旧物理格式，未知或不兼容版本明确失败，不当作空库静默覆盖 |

不新增来源应用排除、隐私过滤或自动粘贴能力。监听开关与内部自动保存状态不能合并为一个语义不明的开关。

### 4.4 内部格式与存储重设计

旧项目已经将图片作为 SQLite BLOB 保存，列表不直接读取完整图片，并有摘要投影及缩略图缓存。新方案复用这些有效思路，同时解除旧传输协议和物理表结构的约束。

| 层次 | 新项目默认设计 | 约束与取舍 |
| --- | --- | --- |
| 领域模型 | 记录、内容、格式、来源、标签使用 Rust 类型和 ID 引用；大段文本与字节缓冲按需共享所有权 | 内部不以 `serde_json::Value` 或 Base64 作为统一数据容器；JSON 保留在配置文件、WebDAV、MCP 等真实协议边界 |
| 热元数据 | SQLite 历史记录保存 ID、排序时间、来源、格式集合、内容引用、修订号、OCR 有效文字状态和列表必要摘要 | 列表查询不连带读取完整 HTML、RTF、OCR 或原图；OCR 状态从完整结果按菜单空白规则在写入时计算，不用截断摘要推断，也不保留无人消费的 OCR 摘要；字数、图片宽高与编码长度等可在写入时计算 |
| 原始载荷 | 完整文本、HTML、RTF、文件路径列表与图片载荷按实际读取粒度分离 | 各格式保留可还原的原始内容，不从清洗预览或缩略图反推原文；派生 OCR 不参与原复制内容身份 |
| 图片载荷 | 默认仍用同一 SQLite 数据库中的独立图片 BLOB 表，以内容引用关联记录，避免热记录携带大 BLOB | 原始编码与像素身份分开管理；可共享相同字节载荷，不以像素等价擅自改写原图；不预建多套 BLOB/文件双写后端 |
| 关系与索引 | 标签、记录绑定、来源和统计按查询需求组织；排序使用时间与 ID 的稳定复合键 | 事务保证写入、去重、关联和清理一致；按实际筛选与排序建立索引，不给每个字段盲目加索引 |
| 格式版本 | 本项目独立 schema、格式身份、摘要算法版本及升级入口 | 首次使用空库；只为本项目未来版本定义升级，不实现旧项目导入或伪装成旧格式 |

优先保持 SQLite 的原子事务，暂不把原图默认外置为文件。只有实际数据量、读写或数据库维护成本证明需要外置时再变更；届时必须一并实现原子发布、引用一致性、崩溃恢复和孤儿清理，不能只将 BLOB 改成路径。

写入路径一次完成格式检查、内容身份计算和必要元数据提取。原始通知摘要、记录等价摘要和图片字节/像素身份各有用途，不能为“减少哈希”混为一谈；像素等价去重仍遵循现有规则，但摘要编码本身不必兼容旧版本。解析预算与失败规则显式定义，不以预览失败拒绝本来可保存、可还原的原始格式。

搜索保留现有匹配范围、标签组合和排序语义。新 SQL、索引或预计算字段必须得到相同匹配结果；不直接改为分词全文检索而改变子串、标点、中文和大小写行为。列表摘要是可重建的派生数据，不能成为完整内容的唯一存储。

数据库访问复用有序后台执行边界，避免 UI 阻塞和大图片解码占用数据库连接；是否增加读连接由实际争用决定。明确事务提交、WAL/checkpoint、磁盘满与损坏时的错误处理，不通过降低持久性来掩盖卡顿，也不在每次复制后执行全库维护。

复制统计与 AI 用量共用核心本地日历边界：小时按本地整点和 UTC 偏移变化分段，以 UTC 毫秒区分重复或部分小时；日/月按本地日期推进，不硬加固定天数或毫秒数。缺失午夜取实际起点，整日缺失跳至下一存在日期；日期筛选、趋势补点与 AI 包容查询上限共用这些边界。完全不存在的自定义开始日期保留明确错误，有效日期的独占结束边界允许跨越不存在的日期。

### 4.5 图片处理与资源生命周期

现有路径为数据库原图 → 后台生成 PNG 缩略图 → WebView 媒体协议 → 浏览器图片解码。新项目直接向 GPUI 图片资源适配层提供解码数据或资源句柄，具体接口按锁定版本实现，不再维护应用内 HTTP/URI 图片传输协议。

- **原图与展示分离**：数据库保留可还原原图。卡片使用与实际绘制尺寸、DPI 匹配的缩略图；详情按需读取较高分辨率，OCR、二维码和剪贴板还原使用对应原始数据，不误用卡片缩略图。
- **避免无用往返**：进程内缩略图默认直接交付解码结果，不为跨 WebView 传输而先编码 PNG 再解码。确需落盘时才编码派生缩略图，格式选择兼顾透明度、显示结果和实际成本；原图不因节省空间有损重压缩。
- **统一图片入口**：去重、尺寸提取、预览、OCR、二维码识别与协议导出统一通过图片服务读取和解码，复用存活的像素缓冲及同键在途任务。阶段结束后按需释放大像素缓冲，具体数据表示与接口遵循 4.7 节。
- **分层标识**：缩略图键包含图片内容身份、尺寸档位、缩放/方向处理和生成器版本。尺寸按有限档位归并，避免每次窗口微调都生成一个变体；原图更新、算法更新后自然失效。
- **独立预算**：分别限制编码载荷、解码像素、GPU 资源及在途任务内存。解码前检查宽高与像素量，预算按实际分配估算，不以压缩文件大小代替解码占用。
- **调度与合并**：同键请求合并为一个后台任务；详情图片处理优先于等待中的可见卡片任务，同级按到达顺序处理，邻近项只做有限预取。详情加入已有共享工作时，优先级沿等待中的解码、像素派生等依赖传递；正在处理的工作保留原许可至完成，优先级不造成重复启动或抢占物理处理。过期请求取消或忽略，多个窗口共享任务时取消一个消费者不能中断其他消费者；最后等待者离开时取消尚未完成的原图读取、解码、派生及编码阶段，成功结果继续按预算保留。已经进入阻塞处理的工作保留实际预算、并发许可与退出跟踪直至完成，不以取消异步等待提前归还资源；原图读取的准入随 SQLite 实际载荷所有权移动。退出先停止上游消费者，再取消图片工作、停止动图解码线程，等待物理处理与已提交的 SQLite 读取收尾，最后回收缓存。 动图后继帧仅使用空闲处理槽，达到展示期限后将同一预读请求按消费者优先级提交准入；取得处理槽后才申请帧像素和工作预算，避免排队预读挤占可见内容资源。
- **文档内排队**：优先装载可见且尚未就绪的图片，再轮流推进到期动图；只遍历可见图片的顺序队列，避免长文档的不可见图片增加逐帧扫描成本。请求通道暂满后由后台主动续接待加载项，不依赖额外重绘触发重试；离开可见范围时移除排队项。
- **GPU 所有权**：应用记录句柄持有者、缓存保留及释放条件，并核对所选 GPUI/Kit 自带缓存。退出可见范围不销毁仍被详情引用的资源，隐藏浮层后按预算回收无引用资源；不重复维护一套功能相同的全局纹理缓存。
- **可重建磁盘缓存**：仅在跨启动重复生成确有收益时启用派生缩略图磁盘缓存；设独立目录、总字节上限、原子写入及清理规则。缓存缺失或损坏可删除重建，原始载荷损坏必须明确报错，二者不可混同。

删除、到期清理与清空历史先提交持久数据变更，再使相关查询、预览与图片引用失效；共享载荷仅在无存活记录引用时删除。后台任务发布前校验记录是否仍存在、内容修订是否有效，不能在删除后重新挂回旧结果。磁盘缓存清理不误删原图，清历史也不能被未释放的页面缓存表现为仍可还原。

### 4.6 页面展示与缓存重设计

旧项目的 WeakMap、`knownVersions/contentUnchanged`、前后端 DTO 复用和媒体协议服务于 JS/WebView 边界；本项目保留“复用未变内容、拒绝过期结果”的效果，不复制这些机制本身。

| 数据或缓存 | 所有者与键 | 更新与回收 |
| --- | --- | --- |
| 历史查询状态 | 查询会话持有筛选、游标、选中 ID 与必要已加载元数据 | 筛选代次变化拒绝旧结果；替换、暂停或关闭读取器时取消旧读取，排队阶段跳过 SQL，执行中的 SQLite 虚拟机按进度检查取消。回调仅属于该次读取，返回或报错时清除，不使用可能中断后续写入的连接级异步 interrupt；数据服务可共享不可变内容，不缓存所有查询组合 |
| 完整内容 | 内容服务按 ID 与内容修订管理，必要时用 `Arc` 共享 | 按需读取，按字节预算回收；列表不持有所有完整记录 |
| 语义预览 | 预览服务按内容身份/修订、实际参与解析的分类与摘要字段、摘要或完整输入级别、解析器版本缓存 | 共享 provider 解析结果；截断输入不能命中完整详情预览；内容或 OCR 变化只使相关项失效。模型与文档的最后等待者离开时取消未完成工作，单个消费者取消不影响其他等待者，成功结果仍可保留；SQLite 载荷读取及修订复核使用同一次需求的取消身份。阻塞解析在出队前及完成后检查取消，已开始的解析继续持有输入预算、并发许可和退出跟踪，真实完成后释放；共享文档保留原始输入及其预算所有权，不额外复制正文 |
| 来源应用图标 | 来源追踪线程按应用名与可执行路径保存共享编码字节，最多 256 项、合计 4 MiB；当前来源及记录共享字节所有者 | 最近使用淘汰，失败或低分辨率结果按窗口切换或既有 5 秒间隔重试；线程退出释放索引。输入最大 8 MiB，普通小 PNG 验证后保留原字节；需转换、缩放或单项超过缓存预算时，复用显示管线处理颜色和方向，缩至 96×96 以内后再按 PNG 持久化；不另建像素缓存 |
| 文字布局 | 先复用 Kit/GPUI 的能力，应用仅保存确有必要的额外结果 | 宽度、字体、字号、DPI 等参与实际依赖键；语义文本不因主题变化重新解析 |
| 视图状态 | 每个视图持有 Entity、输入状态、选择和滚动位置 | 不作为全局业务缓存；视图离开时按既定草稿语义销毁并释放订阅 |
| 配置与状态 | 进程内权威服务及只读快照，表单另持本地草稿 | 不为每个窗口复制完整传输缓存，仍保留并发冲突、pending 与失败回显语义 |
| 标签列表与计数 | 设置页与浮层各自持有一份共享元数据快照、一个在途读取和一个刷新标记 | 事件合并刷新；隐藏与销毁取消 SQLite 读取和逐行组装，等待真实收尾后再刷新，重开不积压旧读取；已接受的标签写入独立完成，不因列表关闭而取消 |
| 统计查询 | 页面仅持有当前筛选的一份共享结果与对应图形；读取合并为一个在途请求及一个最新目标，不额外建立全局查询结果缓存 | 复制/OCR 用量变更只刷新对应统计；筛选变化、隐藏、清空与页面销毁取消旧读取，取消传入 SQLite 及聚合循环，等待实际收尾再运行最新目标；隐藏时暂停刷新，离开页面释放订阅；每次读取重新计算相对日期范围，避免跨午夜后继续使用旧边界 |
| OCR 模型状态 | 设置页持有模型元数据、单次在途读取与刷新标记，模型服务统一持有实际文件读取 | 隐藏、切页或销毁取消旧需求；完成回调先释放槽位，再按代次决定更新或重读；读取期间保留变动模型 ID 并合并最新共享事件状态，进度事件不重新扫描整个目录，漏事件与主动变更仍补读。原有完整校验锁覆盖实际读取收尾。状态查询串行准入，排队取消不访问文件；已开始的读取、完整哈希校验保留到真实收尾，停服统一等待；下载和删除等已接受变更保持独立所有权 |
| OCR 任务状态 | 调度器按记录 ID 与任务代次持有权威状态；浮层仅投影已加载记录的状态，不缓存图片或识别正文 | 进行中状态跟随已接受任务，写回结束前保持忙；最近终态最多 500 项、保留 120 秒，事件与快照共用原始失效时间；截止时间索引在更新/读取时清理过期或超量项，不增加后台轮询；记录删除、到期清理、清历史时移除对应状态，停服清空；窗口隐藏释放投影，重开按需恢复 |

内容修订、元数据修订和查询代次分别表达不同变化。内容修订使用单调版本或等价的可靠标识，不依赖毫秒时间戳在连续更新中碰巧不同。修改标签、来源或使用时间不应重新解码图片；OCR 更新只使依赖 OCR 的预览、搜索与详情失效。

共享资源缓存统一在插入时清理失效弱索引，覆盖异步加载、直接登记和弱别名；淘汰保留值后若无外部消费者，即移除该索引。同键替换先释放旧保留量，再决定是否淘汰其他内容；直接登记命中也更新 LRU，继续复用既有所有者，不重新加载数据。

事件优先携带记录 ID、变更种类及相关修订，更新受影响的已加载范围；排序或筛选变化时重查必要范围，事件缺失时再重读快照。缓存命中不是权威数据存在性的证明，缓存结果不能绕过访问范围或记录删除检查。

VirtualList 只解决绘制范围，不等于内容、解析结果与纹理自动受限。元数据可按现有滚动语义持有已加载范围，完整内容与重资源只保留活动视口、有限预取及打开详情所需部分；render 不执行 I/O、完整解析或列表全量重建。UI 刷新限定到受影响的 Entity，动画停止或窗口隐藏后不为缓存主动申请帧。

每个保留的缓存记录用途、所有者、键、失效条件、容量口径与回收时机。优先使用 Kit 已有且可控的能力；新增缓存必须解决具体重复工作，缓存条目数、TTL、分页尺寸和旧项目的 32 项/16MiB 缩略图预算均不机械继承。不用多级缓存掩盖低效查询或过大的数据传递。

### 4.7 数据流与转换契约

以下类型和方法名表达计划职责，实际签名按所选依赖实现，不预建空服务或占位 trait。图片服务归属 `app-core`，GPUI 资源适配归属桌面 UI，平台与外部协议适配器分别承担自己的格式边界。

#### 4.7.1 共享表示与服务接口

| 表示或操作 | 输入与输出 | 实现约束 |
| --- | --- | --- |
| `EncodedImage` | 原始或必要派生编码，持有共享字节、真实格式及对应元数据 | 用 `Arc<[u8]>` 或适配库的共享字节类型；不使用内部 Base64/data URL；格式探测不代替完整校验 |
| 内部原生解码 | 编码来源 → 带方向/色彩元数据的原精度解码分配 | 8 位保留共享 RGBA8，高位深保留原生布局；规范化像素与显示像素按需派生，不预存三份整图 |
| `PixelBuffer` | 宽高、stride、像素布局、颜色/透明度与方向处理信息，以及共享像素缓冲 | 不强制消费者先转统一布局再转回；处理语义进入派生键，保持现有显示与像素去重规则 |
| `ImageSource` | 编码、原生像素或持久图片引用 | 已有像素不先编码再交给解码接口；持久引用带内容身份与修订，不只按记录 ID 长期命中 |
| `import_encoded` / `import_shared_encoded` / `import_shared_input` | 独占字节、共享字节或预解析来源 → 共享原始编码 | 独占与共享字节共用入口；排队/哈希阶段受工作预算约束，新身份才占编码池，保留 Vec 的实际容量计量。预解析来源复用摘要和头部，不重新编码；未知输入仍需读取字节计算摘要。加入已有任务立即释放多余载荷与预算，排队及计算开始前检查取消 |
| `load_original` | 图片引用 → 共享原始载荷 | 合并同键在途读取；调用方已持有载荷时直接传入，不先写库再读回 |
| `acquire_pixels` | 图片来源与解码策略 → 受预算约束的共享规范化 RGBA8（直接像素来源保留其布局） | 复用同键在途解码和存活结果；高位深按需量化，保持原始指纹/OCR 的语义 |
| `acquire_card_pixels` | 持久图片引用、尺寸与布局 → 静态卡片显示像素 | 基础缩略保留原项目 640px 首帧 PNG 像素语义，再派生预乘 RGBA/BGRA；不进行 PNG 往返，与原图显示分域 |
| `acquire_display_pixels` | 图片来源、尺寸与布局 → 显示像素及自然尺寸 | 从原精度解码校色后量化，RGBA/BGRA 按覆盖率缩放并输出预乘 Alpha；与规范化派生键分域，缓存命中不先读取原图 |
| `acquire_display_frame` / `ImageAnimation::poll` | 共享编码、可选播放检查点与显示规格 → 当前帧、自然尺寸、播放句柄、下次期限和检查点 | 内嵌动图按可见需求共享推进；检查点绑定源身份，恢复时逐帧让出 worker；静态来源复用显示入口，动画显示派生只弱复用；不创建完整帧数组，缓存命中仍检查当前限制 |
| `derive_pixels` | 共享像素与目标尺寸/布局 → 数据派生像素 | 为 RGB OCR、灰度二维码识别按需派生；RGBA/BGRA 保留直通 Alpha，匹配布局可直接借用，不通过 PNG 往返转换 |
| `derive_display_pixels` | 已规范化/原生像素与目标尺寸/布局 → 显示像素 | RGBA/BGRA 输出预乘 Alpha，与数据用途分键；已匹配的预乘输入直接共享，RGB/灰度输出保持数据转换语义 |
| `encode_for` | 原始编码或像素与目标编码/参数 → 共享编码结果 | 已有满足目标且校验有效的字节时复用；确需编码时同键合并，避免复制、保存和导出各编码一次 |
| `upload_image` | 显示像素或受控资源引用 → GPUI 图片句柄 | 桌面共享入口要求紧密预乘 BGRA8，并向着色器传递 Alpha 标记；保持原像素及预算所有者，不复制成 Frame 或重新编码；GPU 上传仍存在 |

解码与编码键包含源身份及真实处理策略，派生键另含尺寸、像素布局和算法版本。内容尚未入库时使用当前采集身份或已计算的编码摘要，入库后建立引用关联，不为取得数据库 ID 增加一次持久化往返。不同编码的像素等价判断仍可能分别需要首次解码，不凭文件头或缩略图推断完整像素等价。

缓存命中仍应用当前消费者的像素量、编码大小、允许格式和协议限制；共享数据不等于共享所有校验结论。校验覆盖范围与编码规范化策略必须显式区分，不能把另一入口较宽松的校验当作当前入口已通过，也不能将同 MIME 的任意原图视作已满足规范化编码策略。

同键在途请求只执行一份重工作；按消费者生命周期管理取消。失败后移除在途项并返回明确错误，不留下永久 pending，不另开解码路径绕过资源限制。缓存回收后的重新解码允许发生，不承诺整个进程生命周期内同图永远只解码一次。

#### 4.7.2 图片从采集到消费的数据流

| 场景 | 目标数据流 | 转换边界 |
| --- | --- | --- |
| 编码图片采集 | 系统可用编码 → 共享编码 → 内容身份与存储；按需取得像素供展示/识别 | 保留可直接使用的编码，不为统一成 PNG 先全图转码 |
| 原生像素采集 | 系统像素 → 共享像素 → 去重、元数据与当前消费者；持久化时生成无损编码 | 平台只提供像素时允许必要编码，同规格消费者复用结果，不制造编码后立即解码的往返 |
| 卡片与详情 | 图片来源 → 共享解码 → 所需分辨率/布局 → GPUI 资源 | 卡片低分辨率结果不能代替详情或像素等价判断需要的完整结果 |
| 本地 OCR | 图片来源 → 共享解码 → RGB/缩放等模型输入 → OCR 结果 | 增加像素输入路径，不继续强制 encoded → decode_image；保留模型专用张量转换 |
| 二维码识别 | 图片来源 → 共享解码 → 灰度 → 检测/解析 | 增加灰度像素输入路径，已有灰度缓冲可直接使用 |
| 二维码生成 | 文本 → 二维码矩阵/像素 → GPUI 展示 | 保留纠错、留白、尺寸与缩放规则，不默认同时生成 PNG 与 Base64 data URL |
| 二维码复制或已有保存入口 | 生成结果 → 系统要求的像素或按需 PNG → 剪贴板/保存 | 只接通当前已有操作，不新增导出功能；同规格编码结果复用 |
| 图片还原 | 持久原始载荷 → 平台接受的编码或像素 → 系统剪贴板 | 平台接受编码时不额外解码；要求像素时复用图片服务结果，保持多格式同时还原 |

平台适配需检查迁入 vendor 的实际读写行为：当前原生路径会将系统图片转换为 PNG，写入时由编码构造平台图片。新项目在同一份本地 vendor/平台适配中补齐必要的像素或编码入口，不在上层另加一套剪贴板实现。后端暂不能直接消费现有表示时，记录具体剩余转换与接口限制；缺口未处理前不宣称完成转换优化。

持久原始图片载荷的含义为：获得原始编码时保留编码；系统只提供像素时保存由其生成的可还原无损编码，不虚构原始文件字节。派生缩略图和远程请求转码结果不替换该载荷。

#### 4.7.3 富文本解析与呈现

- 用共享的受控文档结构表达文本段、样式、段落、列表、表格与内嵌图片引用；原始载荷单独保留，预览模型持有文档共享引用，不为每个视图复制等价中间 HTML 或解析树。优先复用所选库可独立使用的文档模型，必要的应用结构限于现有格式，不另建完整排版引擎，不让核心服务依赖 GPUI。
- HTML 路径为“原始 HTML → 解析时清洗 → 受控文档 → Kit 文本/表格适配”。清洗与解析共用结果，不先清洗生成 HTML 再无条件完整解析一次。
- RTF 优先直接将解析事件/结构转换为受控文档，在满足现有格式能力的前提下减少 HTML 中间表示，按实际缺口扩展选定解析器。
- Kit 只开放 HTML 字符串入口时，优先增加限定的结构化输入补丁或直接消费结构的局部呈现适配。确有无法消除的转换时集中到单个适配器，记录原因、输入输出并共享结果，不让卡片和详情各维护一套 RTF → HTML → 解析树流水线。
- 主题、窗口尺寸和选区变化复用受控文档，仅按宽度与字体等条件重新布局。原始还原与“还原为纯文本”遵循原业务规则，不用预览清洗后的文档覆盖源数据或改变纯文本提取结果。
- 内嵌图片通过受限来源接入图片服务：data URI 在实际引用时解码并共享，不重新包装成 data URI 交给 UI；继续禁止自动获取外部图片。解析与图片载荷都受体积、层级及任务预算约束。

#### 4.7.4 外部协议的必要转换

| 边界 | 编解码规则 | 行为约束 |
| --- | --- | --- |
| 远程 OCR JSON | 在组装请求时对所需编码执行 Base64，已有服务支持的编码直接使用 | 不把图片包装成内部 Base64 再解码组装请求；保留自定义字段、参数与响应路径 |
| 远程 OCR multipart | 直传原始编码字节，按共享原图的 `ImageFormat` 提供真实 MIME 与文件扩展名；未知格式明确失败 | 不附加 Base64 或 PNG 转码中间层；请求体通过共享字节持有原图及其预算，直到实际发送结束 |
| AI OCR | 复用服务支持的原始编码，必要转码集中在协议准备步骤，最后构造 Base64/JSON | 不因 UI 使用 RGB 就先转 PNG；保持提供者支持范围、大小限制及凭据边界 |
| MCP 图片输出 | 保留输出 MIME、尺寸、字节字段、限制及错误语义；由共享图片服务 `encode_png` 准备规范化编码，再在同一受限 CPU 队列执行 Base64 | 当前输出固定 PNG，不直接改发 JPEG；复用已有 PNG 仍须满足校验、规范化与返回字段语义，不只凭后缀跳过处理 |
| MCP 图片输入 | 移交请求字符串，在共享图片服务的受限 CPU 队列解码一次 Base64，解码缓冲及已有工作内存配额一并交给图片入口 | 不经 JSON 转发给内部 OCR 再解码；保留输入限制与格式校验 |
| 外部链接 | 按记录 ID 只读完整原文，复用预览 worker、内存准入和退出排空，检查 HTTP(S)、主机、账号密码及 NUL，返回前复核内容修订 | 共享原始字符串及 trim 范围，不从卡片摘要拼接，不读取其他格式或构造详情模型；解析临时对象随后释放。交给 GPUI 原生打开，其接口不返回浏览器启动完成回执，不呈现未经确认的成功提示 |
| WebDAV 与配置持久化 | 读写边界做必要序列化，内部持有类型化快照 | 不改变同步文档契约；凭据和历史图片不进入同步内容 |

MCP Base64 输入按字符串实际容量、可选空白规范化和解码输出预留工作内存；排队取消或消费者放弃时释放，已开始的 CPU 工作持有输入、配额和任务登记至物理结束。解码输出沿用同一配额进入哈希与原图池，不复制 Vec 或重复申请入口工作内存。输出 Base64 编码的临时分配计入工作预算，完成后的协议字符串由请求和 SDK 持有，不增加图片缓存或另建线程池。

跨请求共享源字节、像素或规范化编码前，仍检查当前记录、配置和访问范围。Base64 与请求 JSON 默认随请求释放，不新增长期大请求体缓存。网络重试可复用同一请求的准备结果，配置、目标编码或权限变化后重新准备。

#### 4.7.5 转换审阅与允许的重复工作

迁入每条路径时记录来源表示、消费者要求、转换位置、所有者和释放时机。完整图片解码、像素布局转换、压缩编码、Base64 与 JSON 分别计数，不统称为一次加载；DB 读取分配、库接口必要复制与 CPU→GPU 上传另行记录，不声称端到端零拷贝。

同源同策略的并发消费者共享一次在途解码，存活缓冲可用时不因进入另一个服务重新解码。不同分辨率策略、模型专用变换、协议要求的规范化，以及资源回收后的再次访问允许必要工作。每处保留的转换对应实际消费者要求，不常驻全部原图以追求全生命周期零重复。

### 4.8 优化落地顺序与证据

先明确原始数据与派生数据、热查询投影、类型化接口和资源所有权，再决定缓存；不能先复制旧缓存，再在 GPUI 上叠一层新缓存。实现顺序为独立 schema 与数据访问 → 共享图片输入/解码/编码及预算 → 平台、OCR、二维码与协议消费者接入 → 统一文档解析与呈现 → 预览复用及增量刷新。

实施时记录与真实路径直接相关的诊断量：列表实际读取的载荷、同图重复解码次数、缓存驻留字节、在途任务、纹理保留及隐藏后的资源释放。集中验证时按实际问题选择必要采样，不搭建额外压测体系、不新增 UI 自动化，不以未经测量的倍数或固定毫秒指标声称优化成功。每项旧优化明确选择保留、重写或删除，并说明它在新架构中解决的具体问题。

## 五、主题与公共控件

### 5.1 主题来源

将现有设计变量迁为一份本地主题定义，同时映射到 Kit Theme 与自定义组件。

- 颜色：窗口、标题栏、侧栏、表面、文字、边框、选中、危险、成功、警告。
- 尺寸：字体、行高、间距、圆角、控件高度和图标；历史卡片的尺寸与内部排版按内容可读性确定，沿用当前可用布局，不纳入原版尺寸复刻。
- 效果：阴影、焦点环、遮罩与透明度。
- 动画：时长、贝塞尔曲线和位移参数。

明暗模式与跟随系统统一处理。主题变化更新样式，不重建输入状态、历史列表或业务请求。

迁移细节包括中文字体回退、等宽字体、换行截断、失焦选中态、DPI 像素对齐和图标落点。卡片加粗边框采用覆盖绘制，避免悬停导致布局抖动。

### 5.2 控件包装

建立 `AppButton`、`AppInput`、`AppNumberInput`、`AppSelect`、`AppSwitch`、`AppDatePicker`、`AppColorPicker`、`AppDialog`、`AppContextMenu`、`SettingRow`、`SettingSection` 等实际需要的包装。

普通控件优先定制 Kit；剪贴板卡片、标签栏和浮层工具栏使用 Base 行为与 GPUI 元素组合。只有公开接口无法复刻的局部才调整组件实现，不复制整个组件库。

每个包装明确正常、悬停、按下、焦点、选中、禁用、加载与错误状态。不能只修改默认颜色，遗漏原有输入和提交语义。

## 六、动画实现

`ui/motion/` 只保存应用动画参数与组合，不重复实现通用补间器、弹簧引擎或帧循环。

| 动画 | 当前参数与行为 | 实现方式 |
| --- | --- | --- |
| 浮层进出 | 四方向滑动并渐隐/渐显；进入 100ms、退出 180ms，共用 ease-out 曲线，反向打断从当前进度继续 | Base transition 同时驱动位移与透明度；透明末帧提交后才隐藏宿主，重新唤出撤销旧隐藏等待 |
| 搜索展开收起 | 250ms，宽度、透明度、缩放、内边距及中间关键帧 | Base Keyframes/Timing，协调标签显隐 |
| 标签指示器 | 位置和宽度约 200ms | Base transition，布局测量确定目标 |
| 控件与卡片 | 多数 100–150ms | Kit 交互样式和必要属性过渡 |
| 菜单 | 淡入或表面出现，子菜单关闭延迟 150ms | 组件动画或 Presence，保留原效果 |
| 应用内弹窗 | Kit 所选版本默认动画 | 使用 Dialog 默认值，不复刻旧弹窗动画 |
| OCR 等待 | 旋转加载状态 | Kit Spinner，隐藏时停止 |
| 快捷标记 | 透明度和位移 | Base transition |

实现约束：

- 应用自定义动画保留现有贝塞尔曲线，不用默认弹簧改变手感；Dialog 使用 Kit 默认值。
- 稳定 ID 区分组件和动画通道；卡片使用记录 ID，不使用列表下标。
- 逻辑关闭后保留必要挂载，退出结束再卸载或隐藏原生窗口。
- 快速反向、重复打开和取消遵循当前交互语义；需要中途转向时使用 Base 可中断机制。
- 完成通知携带显示代次，旧动画不能隐藏新打开的浮层。
- 绘制裁剪与命中区域一致，不留下不可见控件拦截输入。
- 动画停止后不持续申请帧；系统减少动态效果时正确收敛到终态。列表滚轮、键盘选中定位采用即时位置更新，拖动不追加惯性；在途自定义滚动于偏好变化后一次性收尾。
- 系统偏好运行中变更继续跟随：macOS 使用 NSWorkspace 辅助显示选项通知，Windows 使用既有隐藏顶层窗口接收系统设置广播，Linux 先订阅 Portal 再首次读取。共用 Base 的应用覆盖策略，不新增轮询或动画循环。
- 列表动画以旧版实际运行效果为准，不把仅存在于 CSS 中的规则直接当作已启用功能。

## 七、剪贴板浮层

### 7.1 状态划分

- `OverlaySession`：显示代次、方向、目标屏幕、显示阶段和焦点信息。
- `HistoryState`：查询、记录、选中记录、分页、加载与错误。
- `SearchState`：输入控件、组合输入、查询版本与防抖任务。
- `InteractionState`：拖动、菜单、详情窗口与快捷选择。

显示流程：准备数据和位置 → 布局与首帧准备 → 显示和激活 → 进入动画 → 交互 → 退出动画 → 隐藏及焦点处理。

替换旧 WebView 快照屏障时，核对所选 GPUI 后端的帧提交机制。一次 `notify()` 不代表画面已经提交，不能直接作为显示就绪信号。

### 7.2 搜索与键盘

- 保留 300ms 防抖，组合输入期间不搜索、不把 Enter 当作粘贴。
- 查询变化丢弃旧结果，并取消旧查询对应的排队导航和确认操作。
- 还原操作执行时拦截重复提交。
- 输入框编辑快捷键、历史导航和修饰键快捷选择分层处理。
- 菜单、下拉和详情窗口捕获自身按键，避免穿透到浮层。
- 保留清空搜索、Esc、方向键、Home/End 和选中项自动可见的现有规则。

具体键位契约如下，原实现参考 `useSearchAndNavigation.ts` 和 `pages/overlay/index.vue`：

| 输入 | 行为 |
| --- | --- |
| Ctrl/Cmd + 1…9 | 还原当前结果中的对应记录；只对前九项显示快捷标记，不重复执行长按确认 |
| 左/右 | 前后移动一项；Ctrl/Cmd 修饰时移动五项，到边界停止 |
| 上/下 | 前后移动一项；Ctrl/Cmd + 上/下分别跳到首项和末项 |
| Ctrl/Cmd + Home/End | 非搜索输入焦点时跳首尾；输入框中的 Home/End 保留文本编辑行为 |
| 输入框中 Shift + 方向键 | 保留文字选区，不移动历史选择 |
| Enter | 非组合输入、非重复提交时还原选中记录；按钮焦点下 Enter/Space 激活按钮 |
| 普通字符 | 工具栏焦点后继续输入时转回搜索输入，并保留当前字符和插入位置 |
| IME 组合输入 | 方向键、Enter、Esc 交由输入法，不触发应用导航或还原 |

独立详情窗口的 Esc 仅关闭详情并返回面板，不穿透到浮层；详情内存在 Kit Dialog 时先由其处理。应用级 Esc 顺序为：优先让当前 Kit Dialog 或菜单处理；工具栏下拉打开时只关下拉；搜索展开且有查询时聚焦并清空查询；查询为空时收起搜索；搜索已收起才关闭浮层。弹窗内部 Esc、遮罩点击和焦点处理采用 Kit 默认值，事件不得继续穿透执行底层浮层操作。

修饰键快捷标记还要迁入原生修饰键状态、失焦清理和输入法吞键处理，避免 Ctrl/Meta 已释放后标记仍停留。

### 7.3 列表与滚动

复用 Kit 横向和纵向 VirtualList，按浮层方向选择布局轴。应用负责分页、选择、滚轮映射和手势语义。

- 临近末尾加载下一页，同一查询不重复请求。
- 单页读取上限不作为可浏览历史总量上限；刷新和重新打开按已加载范围分批读取，统一处理取消、过期及失败，保留范围末尾的继续分页游标。
- 更新后按记录 ID 保持选择和滚动锚点，删除与筛选后正确收敛。
- 拖动超过 6px 后抑制点击；保留现有惯性、速度平滑和滚轮加速参数。
- 详情正文、菜单和输入控件的滚动不误触历史列表。
- 卡片几何由新布局统一确定；异步预览与图片加载不使列表位置和滚动锚点跳动。
- 按 4.6 节管理内容与展示资源，不将虚拟列表视为内存回收机制。

查询按最近使用时间降序及稳定 ID 次序排序，搜索文本 trim 后与当前标签一起构成筛选身份，使用游标分页。刷新受影响的已加载范围，并按内容修订复用未变化内容，不照搬 `knownVersions/contentUnchanged` 传输协议。筛选变化回到首项；停在头部且选中首项时跟随新首项；手动浏览时尽量保留原选中 ID，记录消失则夹取有效索引，不能每次通知都滚回头部。初次加载、加载更多、失败和重试分开建模，过期响应不得修改新查询的选择、游标和错误状态。

## 八、内容预览

保持 provider 优先级：文件 → 图片 → 颜色 → 富文本 → 链接 → 联系方式 → JSON → 代码 → 表格 → 文本。

建立不依赖 GPUI 的 `PreviewModel`，卡片与详情共享识别和规范化结果；GPUI 层只负责呈现和交互。

| 内容 | 实现要求 |
| --- | --- |
| 文本 | 复用文字选择，保留空白提示；卡片的字号、换行与截断按可读性设计 |
| 代码 | 保持现有等宽样式，详情保留横向阅读能力 |
| JSON | 迁入按原始字符格式化的逻辑，保留大整数和重复键，不重新序列化 |
| 图片 | 按 4.5 节使用原生图片流水线，保留尺寸、透明度和失败反馈，不迁入 WebView 媒体协议 |
| 文件与链接 | 自定义紧凑布局，保留来源、摘要、复制及打开行为 |
| 联系方式与颜色 | 迁入检测和格式转换规则，保持菜单与复制结果 |
| 表格 | 复用 TextView/Table，补齐尺寸、复制和合并单元格差异 |
| HTML | 解析清洗后生成共享受控文档，接入 TextView/表格适配，补齐差异 |
| RTF | 优先直接生成受控文档，按 4.7.3 节管理确有必要的中间适配 |

### 8.1 富文本格式对照

Kit 已有常见 HTML、表格、图片、选择和复制能力，但不等同于浏览器完整排版。实施时以旧应用现有白名单为范围，逐项核对：

- 前景与背景色、粗体、斜体、下划线、删除线。
- 段落对齐、空白保留、上下标、列表编号和嵌套。
- `colspan`、`rowspan`、预览固定样式的单元格边框、内边距和布局。
- 内嵌图片、尺寸约束、替代文字和加载失败。
- 暗色主题下仍保留现有富文本白纸背景。
- 详情选择、复制、滚动和纯文本切换。

缺口按公开接口 → 局部扩展 → 固定上游补丁的顺序处理。不得用纯文本或截图静默替代尚未完成的现有富文本能力。

RTF 转换器需要确认中文编码、颜色、表格、图片和异常输入，不能将基础标签转换能力当作完整兼容证明。

作者 CSS 的尺寸、字体族/字号、边距、内边距和边框不在旧预览的九项样式白名单中，HTML 属性也不保留尺寸。表格使用预览自身的固定样式；作者行/行组高度、百分比尺寸和任意边框冲突不作为迁移缺口，不为其增加解析或布局能力。

清洗与资源策略继续保留：预览不自动加载外部图片；限制解析体积和结构复杂度；原始剪贴板数据保持不变；解析失败展示明确提示，并按现有规则使用可用的文本预览。

### 8.2 可见细节与类型菜单

- 解析和识别继续保留必要资源边界：富文本上限 200000、结构化文本检测上限 20000，保持原字符计数语义，不统一替换为 UTF-8 字节截断。卡片摘录长度、文件可见行数与表格可见行列按新布局的可读性和原生控件能力确定；旧版文本摘录 12000、文件四行、表格八行四列不作为复刻验收参数。卡片截断不改变原始内容，完整详情继续按需读取。
- 图片保持透明棋盘底、等比适配、附文和首文件名；附文长度与可见行数按卡片空间安排，不要求复刻旧版 300 字符及三行显示。详情读取完整记录后显示自然尺寸与字节摘要。
- 详情按现有内容条件提供“排版/原文”切换，卡片摘录不能冒充完整详情。切换时清除旧展示模式的选区，键盘激活也执行相同清理；继续复用正文状态，不让隐藏内容参与复制。详情窗口按内容和工作区设置初始布局，正文格式、选择和滚动由业务内容实现。
- 详情加载时禁用重复打开并显示加载状态；记录 ID、内容版本变化或视图销毁后丢弃旧响应。
- 通用菜单提供纯文本还原和删除；纯文本还原仅在 text/HTML/RTF/files 可用时启用。
- 图片菜单按 OCR 是否存在显示复制 OCR、解析或重新识别；任务忙时禁用重复 OCR，同时提供二维码解析。
- OCR 存在判定读取完整结果在保存时派生的热状态，保留 ECMAScript 空白语义；不以摘要长度或截断后的空白推断，也不为打开菜单读取完整 OCR。
- text/HTML/url 主类型按现有规则提供二维码生成；链接提供外部打开，摘录不足时先读取完整记录。
- 颜色提供 HEX/RGB 复制；标签子菜单显示已绑定状态、颜色及当前标签移除入口。
- 类型菜单的显示、禁用与排序迁入现有 provider 规则，不只按预览类型做一组固定菜单。

## 九、设置和反馈

迁移九个区域：通用、同步、OCR、MCP、标签、统计、快捷键、调试、关于。使用公共设置行与控件组合，不引入额外路由框架。

配置状态区分后台已提交快照、本地编辑值、待提交变更和提交错误。保留字段并发控制、操作身份、凭据变更路径和后台校验的语义，不要求保留 IPC 的序列化字段或桥接缓存；回显后台结果不能再次触发提交形成循环。

### 9.1 区域与提交规格

| 区域 | 字段和操作 | 提交与生命周期 |
| --- | --- | --- |
| 通用 | 主题、自启动、静默启动、浮层方向、历史数量、保留天数、清历史 | 即时提交；数量 10–1000，天数 -1 或 1–365；预设数值显示 200ms 动画，滑块和键盘即时；清历史先确认 |
| 同步 | 启用、WebDAV 提供者、方向、间隔、地址、用户、密码、路径、超时、HTTPS、测试与手动同步 | 本地草稿、显式保存和重置；间隔 UI 用分钟、服务用毫秒；测试连接及手动同步前提交未保存配置，保存启用配置后测试连接；未启用定时同步时仍允许用当前配置手动同步 |
| OCR | 自动 OCR、模式、本地模型、远程地址/参数/字段/格式/结果路径、AI 提供者配置与凭据、模型管理 | 草稿保存和重置；额外参数 JSON、模式对应字段与凭据按原规则校验；模型操作和 AI 测试各自管理 busy 与结果，不并入普通表单保存 |
| MCP | 启用、端口、API key、刷新、生成 key、端点和客户端说明复制 | 显式保存；生成 key 只更新表单，保存后生效；刷新已加载配置时不覆盖正在编辑的表单 |
| 标签 | 列表、创建、编辑名称与颜色、删除、记录绑定 | 编辑弹窗确认才提交；失败保留错误结果，列表与浮层计数通过服务事件更新 |
| 统计 | 复制统计、AI OCR 用量、日期和聚合筛选、清除 | 查询参数不写成应用配置；读取与清除独立操作；切换标签释放离开的子视图订阅 |
| 快捷键 | 录制、预览、校验、清空、取消、系统访问状态与重试 | 有效组合释放后提交，注册失败返回错误；取消录制不保存候选值 |
| 调试 | 监听开关、打开浮层、导出诊断 | 监听等待提交结果；打开浮层和导出诊断调用宿主能力，不伪造成配置保存 |
| 关于 | 版本、应用信息与链接 | 只读展示，版本来自本项目；链接使用受控外部打开入口 |

切换设置区域按现有动态组件生命周期重建局部视图，未提交的局部草稿不自动跨区域保留，也不新增离开确认。导航保留 Up/Down/Home/End。默认配置、字段选项、范围和反馈文案以迁入的配置类型、校验和当前组件为准，不能用 Kit 控件默认值替代业务默认值。迁移每个区域时补齐实际字段与服务调用对应关系，业务字段不得因本表按组列举而遗漏。

初始默认值从 `src/shared/preferences.ts`、OCR/MCP 共享定义和 `src-tauri/src/config/validation.rs` 复制为新项目本地类型与校验，保持单一来源。例如历史数量 100、保留天数 -1、浮层在底部、自启动与静默启动关闭；同步默认关闭、间隔 30 分钟、双向，WebDAV 超时 30000ms。不要从旧用户配置读取这些默认值。迁入时保留主题、模型和提供者枚举对应的业务默认值，避免抄写成会漂移的第二份表。

### 9.2 配置合并与副作用

- 为客户端、提交和字段维护相应身份、最新提交标记与 pending 状态，同一提交来源串行执行；跨来源冲突仍由权威配置服务处理。
- 提交前获取对应字段的权威版本，提交后接收权威快照、字段版本和凭据状态。
- 其他来源的更新只回显到没有 pending 的字段；同一字段旧请求的结果不能覆盖更新的本地编辑。
- 失败或响应不完整时，仅将仍属于该请求的字段收敛到权威值，清理其 pending 并展示原有错误；不回滚其他字段或较新的提交。
- 进程内共享快照可替代 IPC 缓存和序列化，但不能以共享一个可变对象取代草稿隔离和冲突规则。
- 配置提交后的副作用保持单次执行：主题更新、浮层方向重排、快捷键重新注册、自启动、监听、OCR 与同步调度等由对应服务消费，不依赖旧 Tauri emit 顺带触发。
- 凭据的保留、设置、清除必须区分；空输入不能误删已存密码，明文不能进入普通快照、日志或 WebDAV。

### 9.3 反馈与统一弹窗

反馈逐项接入：

- 历史：加载失败、重试、空历史与无搜索结果。
- OCR：排队、运行、错误和结果更新。
- 模型：下载进度、取消、失败、重新下载和删除。
- 同步：连接测试、保存、同步中、成功、失败与重启提示。
- MCP：服务状态、配置保存、密钥生成和复制反馈。
- 标签：创建、编辑、删除、绑定和计数刷新。
- 统计：日期筛选、图表、无数据和清除确认。
- 危险操作：确认、取消、执行失败和成功结果。
- 详情：请求中、失败、关闭以及过期请求忽略。
- 即时设置：通用、调试和托盘的提交失败仅记录日志；快捷键录制失败保留原位错误，不增加全局保存失败弹窗。

复用 Kit Alert、Progress、Spinner、Dialog 和 Tooltip 等能力。应用内弹窗统一走默认 Kit Dialog，包括旧原生确认和消息框；保留消息内容、触发条件和结果含义，不定制弹窗焦点、模态和关闭策略。危险操作只有显式确认才执行，取消、关闭或弹窗创建失败都不得视作确认。

页面内反馈仍保持原位置、文案和消失时机，不全部改成 Dialog 或 Toast。Dialog 结果适配层统一返回确认、取消或错误，并在所属窗口销毁时结束等待，避免服务任务永久阻塞。

旧实现中仅记录日志的失败行为单独列明；新增可见提示属于交互调整，不能作为迁移默认扩展。

### 10.2 窗口规格

- 尺寸使用工作区逻辑单位，保留任务栏、屏幕偏移与每屏缩放处理。
- 设置窗宽度为工作区宽度的 78%，取整后限制在 960–1400，再不超过工作区宽；高度按 82%、640–1000 及工作区高处理，初始居中。
- 设置窗最小尺寸分别为初始宽与 720、初始高与 520 的较小值。保留自绘标题栏、最小化、最大化、拖动和八方向边缘缩放；关闭为隐藏。
- 浮层厚度为工作区高度的 36%，取整、限制在 260–480，再不超过工作区高。顶/底横跨工作区宽；左/右占工作区高，宽度取厚度且不超过工作区宽。
- 两窗口均无系统装饰；浮层透明、置顶、不可缩放，退出动画后隐藏。设置窗口与浮层的任务栏/激活行为按平台迁入，不用 Kit 默认普通窗口替代。
- Dialog 使用其默认尺寸、布局壳与交互规则；以上窗口尺寸契约不要求复刻旧 Dialog 壳。

### 10.3 平台接入与资源

- 窗口：设置与浮层的创建、关闭语义、置顶、多屏、工作区、缩放及失焦行为。
- 焦点：来源窗口跟踪、来源恢复、打开设置时取消旧浮层激活、延迟焦点事件的代次校验。macOS 来源通知观察者在主线程注册和释放，来源工作线程在清理时等待主线程队列容量，避免队列饱和丢失释放任务。
- 快捷键：迁入现有 global-hotkey、portal 和修饰键处理路径，替换 Tauri 包装。
- Wayland：核对后端的 surface role、layer shell、激活和输出定位；旧 GTK Layer Shell 不能直接用于 GPUI 窗口，原始窗口句柄也不能直接解决该缺口。需要时在本项目的固定后端补丁中扩展。
- 托盘：统一类型化动作与状态，保留设置、粘贴面板、主题、自启、自动 OCR、重启和退出菜单。Windows/macOS 资源只在 GUI 线程创建、更新和释放；Linux SNI 使用 Tokio/D-Bus，等待桌面宿主上线并处理重连；X11 在宿主离线时按需创建 GTK 3 XEmbed 图标与系统菜单，宿主恢复时隐藏并收起兼容菜单。GTK 控件、信号和销毁均在同一线程，单个最新值通道驱动 GLib 事件任务；兼容后端首次启用后保留线程至退出，后续切换复用，不轮询或反复初始化 GTK。KDE 激活令牌通过限定 ksni 补丁单次传递，菜单非窗口动作也消费令牌。Wayland 不创建 XWayland 兼容图标。状态更新为单个在途任务加最新值，不轮询；菜单配置切换复用即时配置模型及失败回滚，退出等待原生资源回收。
- 单实例与自启动：本项目独立标识，明确再次启动时的激活行为与冲突结果。自启动固定传入 `--background`，普通启动才读取静默启动配置；后台二次启动不唤起已有窗口。Linux 桌面条目、Windows 当前用户注册表及 macOS LaunchAgent 在启动对账时更新当前程序路径和参数；Windows 路径加引号，macOS 文件使用原子替换及内容冲突检查，并保留完整原字节供配置失败回滚。
- 文件对话框与外部链接：父窗口、取消、失败及受控打开策略统一处理。
- 权限与电源：迁入系统访问检查、休眠恢复、监听重启和后台任务取消。电源入口去重重复状态，首次通知仍处理；唤醒等待以有效事件的原始截止时间计时，重复唤醒不延长等待或再次重启采集。
- 资源：本目录独立准备 ORT 和模型清单，解析运行库和模型路径，不读取父项目资源。
- 生命周期：正确关闭 OCR、同步、MCP、监听任务和数据库，再退出或重启。

ORT 保留动态加载方式：开发、安装后和便携运行分别解析本项目准备的运行库位置，包含需要的伴随动态库；不以当前工作目录或父项目已安装的运行库作为隐式兜底。模型清单随本项目分发，下载、取消、缓存、校验、重新下载与删除走独立数据目录。模型或运行库失败必须返回对应服务错误，不伪造 OCR 成功。

数据目录、日志、诊断导出、模型目录和资源目录分别定义，不混用可写数据与只读安装资源。启动、关闭和重启要明确错误传播与任务取消边界；渲染后端无法初始化时保留可定位的错误信息，不将未创建窗口当作正常静默启动。

移除 WebView 依赖后重新计算平台打包依赖；不能据此假定所有 GTK 或系统依赖都已消失。安装配置、许可证和资源复制全部在新项目维护。

### 10.4 独立开发与打包入口

所有命令从仓库根目录运行，使用 `rust-toolchain.toml` 和本项目锁文件；自动构建入口为 `node scripts/build.mjs`，Release 与 AUR 发布入口见 README。

```sh
node scripts/prepare-ort.mjs
cargo run --locked --package super-paste-desktop --bin super-paste

# 首次安装独立打包工具；脚本不会自动安装工具。
cargo install cargo-packager --version 0.11.8 --locked
node scripts/package.mjs
```

`package.mjs` 需要 Node.js 20+，按当前宿主选择本机目标，不交叉封装。默认生成 Linux DEB、macOS DMG 或 Windows NSIS；`--formats deb,pacman` 可在 Linux 一次生成两种包，Linux 另支持 `appimage,portable`，Windows 支持 `nsis,portable`，macOS 支持 `app,dmg`。便携包保留可执行文件旁的 `resources/`，macOS 使用 `.app/Contents/Resources`，DEB/Pacman 使用 `/usr/lib/super-paste`，均与运行库定位代码一致。输出位于 `dist/<target>/<version>/`；构建目录固定为本项目 `target/`，临时封装目录在结束或失败后清理。模型权重继续按需下载，不放入安装包。Pacman 还需要宿主已有的 `makepkg`、`fakeroot` 及其打包依赖，入口只构建、不安装；在 cargo-packager 生成源归档后继续产出 `.pkg.tar.zst`，保留对应源归档和 `PKGBUILD`。配方仅复制应用的 `usr/` 目录，避免带入源归档临时链接，禁用剥离和调试包拆分，保持主程序与 ORT 摘要不变。DEB/Pacman 和 AppImage 的桌面入口统一使用 `com.v2dawn.superpaste.rs.desktop`，与 GPUI 应用标识一致。

AppImage 使用 PATH 中的 `linuxdeploy`、`appimagetool`，入口先记录工具版本；使用工具自身的解包执行模式，不要求打包宿主挂载 FUSE，也不调用 cargo-packager 的 AppImage 后端。本机已核对的工具为 linuxdeploy `07333c6` 与 appimagetool `11d54c9`，官方预编译工具的下载来源和摘要记录在 `target/appimage-tools-provenance.json`。`node scripts/package.mjs --formats appimage` 沿用相同 release 构建与应用资源准备，在独立临时 AppDir 部署依赖后恢复原始资源，逐项检查清单摘要，再封装镜像；主程序保留部署工具写入的相对 RPATH。AppRun 从自身目录定位程序与库，不依赖调用者的当前目录，原样传递参数。镜像运行时按 `packaging/linux/appimage-runtime.json` 的尺寸与 SHA-256 下载、校验并缓存到本项目 `target/package-tools/`，通过显式 `--runtime-file` 传给封装工具；下载失败或摘要不符时报错，不接受移动标签的新文件。运行时来源定义和上游原始许可证另附在镜像内。

AppImage 原生依赖材料收集支持 Arch 的 pacman 数据库和 Debian 的 dpkg 数据库：按实际部署共享库查找宿主文件及所属包，保存原始声明、版本、来源与部署摘要；复制包自带许可目录、可用的对应 SPDX/通用文本以及 Debian copyright 明确引用的通用许可证，原文按 SHA-256 共享。材料缺失、归属不明确或缺少引用文件会使封装失败；不会用项目许可证替代。当前已核实 Arch 分支；Debian 分支仍待实际构建验收，完整发行条件不由该材料索引自动判定。

Windows 使用 Visual Studio MSVC 开发者终端及 Windows SDK（`rc.exe`、GPUI release shader 所需的 `fxc.exe`）；可用 `RC` 指定资源编译器。目标系统需要匹配的 Microsoft Visual C++ x64 运行库。macOS 需要 Xcode/Metal 工具链，应用最低系统版本与构建部署目标统一为 13.3；可用 `SUPER_PASTE_MAC_SIGNING_IDENTITY` 向打包器传递签名身份，签名和公证不属于已验证结果。Linux 需要对应的本机 C/C++、pkg-config、图形/字体和 GTK 3 开发库及所选包格式工具，运行时依赖写在 `packaging/packager.json`；会话 D-Bus、系统凭据服务及可用 GPU 驱动由桌面提供。依赖清单仍需在实际 release 产物上核实，不据静态配置宣称可独立部署。

打包配置按 [cargo-packager 0.11.8 的配置契约](https://docs.rs/cargo-packager/0.11.8/cargo_packager/config/struct.Config.html) 维护；资源逐文件映射，不复制父项目、开发缓存或已下载的模型权重。ORT 准备和封装共用清单校验：限制清单大小，核对目标和版本、主库和许可证声明、文件名唯一性及摘要格式；新资源通过后才替换旧目录。复用已有资源和复制到封装目录时分别校验对应文件的 SHA-256，并生成资源摘要清单；不会仅因文件存在或清单列表为空而接受不完整的运行库。Linux 便携包、DEB、Pacman 与 AppImage 入口及上述包内容核对已通过，具体产物与记录见当前状态；实际安装运行、跨发行版兼容及其他平台仍待验证。

打包入口按当前目标的 Cargo 解析图收集正常与构建依赖的许可证原文和声明，排除仅开发依赖边；生成 `licenses/rust/NOTICE.txt`、`index.json` 和按 SHA-256 共享的原始材料。缺失声明、主许可证、声明的文件或材料为空时，在准备 ORT 和 release 构建前报错；不为第三方包套用本项目许可证，不改写许可证选项。图标声明另行复制，ORT 继续附带自己的声明。工作区特性解析可能多收集依赖，该索引不等于二进制链接清单；Rust 工具链、原生库及实际发行条件仍需随真实产物审阅，已执行的封装与核对范围见前文当前实施状态。

## 十一、实施顺序和交付闭环

以下按代码依赖推进，不代表逐阶段分别执行一轮测试。最终实现和集成稳定后统一验证；只有具体实现阻塞需要检查结果决定方案时，才执行最小范围诊断。

1. **固定依赖与复刻基准**：选择 Kit 版本，记录父项目参考提交与必要已有修改，整理控件、格式、动画和平台行为清单。
2. **创建独立工程并重整数据层**：配置独立 workspace、版本和锁文件，复用业务与必要资源；设计新 schema、类型化数据接口与事件，完成 Tauri 解耦；建立共享图片来源、在途任务合并及资源预算，改造平台读写入口。
3. **建立宿主**：完成两个窗口、生命周期、焦点、快捷键和系统入口；优先解决 Wayland 窗口能力，不能在缺少平台闭环时假定仅需换 UI。
4. **建立主题和公共控件**：将设计变量映射到 Kit，完成实际需要的控件行为和样式。
5. **完成数据消费者与预览管线**：接入 OCR/二维码的像素入口、二维码生成展示及远端/MCP 编码出口；保留 provider 规则和可见摘要，完成统一文档解析、图片交付、预览复用及详情请求，删除旧传输缓存；补齐 HTML/RTF 格式。
6. **完成浮层闭环**：接通搜索、标签、虚拟列表、导航、菜单、还原、删除、OCR、二维码及动画，UI 调用已接入公共数据路径的服务。
7. **完成设置闭环**：完成九个区域、配置提交、进度、错误与重启反馈。
8. **集中验证与独立交付**：集成审阅后统一执行必要 Rust 检查和已有可复用业务验证，完成独立资源与打包入口；UI 由用户人工对照验收，不新建 UI 自动化。

仓库现只维护 Rust + GPUI 实现；旧 Vue/Tauri 源码通过 Git 历史追溯，不保留双宿主或旧构建链。版本、锁文件、发布标签、平台包和 AUR 元数据保持一致。

## 十二、完成标准

- 本目录单独放置后可通过自身入口构建和运行，不依赖父项目源码、资源、脚本或产物。
- 依赖、锁文件、版本、安装配置、资源与许可证完整归属新项目。
- 历史记录、搜索、标签、还原、预览、OCR、同步、MCP 和设置形成完整操作闭环。
- 历史卡片允许独立布局，以内容清晰、浏览便利、状态反馈完整和交互可用为标准，不以原版卡片视觉参数验收，也不为其细节增加底层排版工作。优先沿用 GPUI Kit 和现有可用布局；卡片重设计不作为其他业务的前置条件，后续优先补齐业务功能。
- 除本方案明确允许的卡片布局、弹窗默认行为和渲染差异外，现有控件状态、键盘语义、动画、错误反馈和取消行为无已知遗漏。
- 弹窗统一为 Kit 默认外观与行为；其他复刻界面允许字体栅格化和抗锯齿细微差异，不放宽明显布局、换行或命中偏差。
- HTML/RTF 格式缺口明确处理，不以降级占位声称完整复刻。
- 首次启动独立初始化，不导入旧数据、不接管旧凭据；系统资源冲突有明确结果。
- 内部 schema 与缓存按新架构设计，不绑定旧物理格式；原始内容可完整还原，缩略图与预览可重建。
- 图片、解析结果与页面资源具有明确预算、失效及回收规则，不保留仅为旧 IPC/WebView 存在的重复层；优化结论有实际路径依据。
- 同键并发图片读取、解码与编码合并，已有像素和解析结构在消费者之间复用；内部不以 PNG/Base64/JSON 绕行传递，必要协议转换只在明确边界执行。
- 二维码生成展示不依赖 data URL；OCR 与二维码识别有像素输入路径，RTF/HTML 共用受控文档与解析结果；各平台或依赖限制导致的剩余转换明确记录，不伪称已消除。
- 必要非 UI 验证集中执行并记录实际结果；未运行和未验收的平台明确标注。
- UI 由用户人工验收；不因单平台编译成功宣称跨平台业务通过。
